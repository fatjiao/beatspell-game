# Beatspell 内部试玩版设计

## 目标

把当前直接进入倒计时的开发场景整理成一个可以交给外部玩家启动、理解、游玩、暂停、结算和反馈的内部试玩版本。此批次完成视觉整理与 Windows 导出准备，不加入剧情、Steamworks 或新玩家键位。

## 流程

启动后先进入标题状态。标题只显示游戏名、核心描述、三种术式符号和较小的开始/校准说明；`J/K`、Enter 或 Space 开始两秒倒计时，`C` 进入校准，Esc 退出。战斗中 Esc 返回标题，`R` 仍然立即重开。这样导出包不会在玩家还没准备时自动开始音乐。

标题、倒计时、暂停、阶段切换和结算从主战斗脚本拆到独立 `BattleOverlay`。战斗场景继续绘制角色、Boss、节拍环、术式卡和生命值；覆盖层只接收显示数据，不接管节奏时钟和战斗规则。

## 第三种 Boss 节奏

在现有标准 `[0,2,4,6]` 和切分 `[0,3,4,7]` 之外增加 Rush `[0,4,6,7]`，形成一拍、长休止、随后快速三连的预警轮廓。第一阶段只用标准，第二阶段标准/切分交替，第三阶段切分/Rush 交替。三种攻击都在小节末造成一次伤害，因此 AEGIS 行为不变。

三种预警使用同一八分拍轨道，但通过间距和颜色区分：标准粉色、切分橙红、Rush 金色。不显示模式名称或下一键提示。

## 视觉反馈

火球命中和 Boss 攻击会让世界层短暂震动，HUD 保持固定；阶段切换由覆盖层显示短暂色块与阶段名称。背景光环随阶段提高亮度与暖色比例。暂停和结算覆盖层保留战斗画面作为上下文。

## 试玩与打包

新增 `export_presets.cfg`、`docs/PLAYTEST.md` 和 `CHANGELOG.md`。导出目标为 Windows x86_64，产物进入被忽略的 `build/`。如果本机缺少 Godot 导出模板，至少验证资源包导出配置，并在接力文档中保留准确安装步骤；不会把引擎或构建产物提交到 Git。

## 验收

- 启动停在标题，不自动消耗倒计时。
- 键盘和已有手柄映射均可开始游戏。
- 标准、切分、Rush 三种预警均有自动测试与截图。
- 阶段切换、受击震动、暂停、胜负结算不改变节奏逻辑。
- 全套测试、主场景启动、截图回归和可执行的导出检查通过。
