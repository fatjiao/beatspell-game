# 《一个人的乐队》Demo 设计文档

## 项目定位

《一个人的乐队》是一款面向普通玩家的 Windows 轻音游。玩家扮演中性街头音乐人 Loop，通过四个按键分别演奏电子鼓、贝斯、合成器和主旋律，把空白舞台逐层搭建成完整的电子流行演出。

Demo 只包含两章、六个关卡，目标游玩时长为 20～30 分钟。它首先用于内部验证节奏手感与分层演奏体验，不立即用于商业发布。

## 核心体验

每首歌曲分为三个阶段：

1. **排练**：展示节奏，不扣分。
2. **录制**：玩家依次录入各个乐器的短节奏；录制完成的音轨自动循环。
3. **合奏**：四个乐器全部播放，玩家轮流接管不同乐器，追加重音、Fill 和短旋律。

四个按键各自对应一个乐器，但普通难度下一次通常只操作一个按键，高潮处最多同时操作两个按键。失误只会产生走音、降低热度或改变观众反应，不会中断歌曲。

## 操作与判定

键盘默认布局：

- `D`：电子鼓
- `F`：贝斯
- `J`：合成器
- `K`：主旋律

手柄使用四个正面按键。输入事件分为点击、长按开始和长按释放。判定分为 Perfect、Good 与 Miss；玩家可通过延迟校准修正音频设备造成的偏移。辅助模式扩大判定窗口并自动完成复杂节奏。

## Demo 内容

### 第一章：地下通道

冷蓝、灰紫色调，音乐约 105～115 BPM。

1. 空箱鼓：单键跟拍。
2. 旧贝斯：听完后模仿短节奏。
3. 第一个观众：鼓与贝斯轮流接管，完成第一首歌。

### 第二章：深夜咖啡馆

暖橙、深紫色调，音乐约 120～128 BPM。

1. 雨天和弦：加入长按与释放。
2. 咖啡机节拍：环境音和弱拍参与演奏。
3. 闭店演出：四种乐器轮流接管，形成 Demo 高潮。

Demo 结尾展示公园、酒吧与音乐节的剪影，并以音乐节招募海报作为正式版钩子。

## 美术与叙事

采用现代 16-bit 像素风，内部渲染分辨率为 320×180，再进行整数倍放大。主角高度约 48 像素，固定站在横向舞台上。每件乐器只制作待机、演奏、失误和结束四组基础动画，依靠灯光、粒子、场景反应和轻微镜头震动增强表现。

主角 Loop 不强调性别，穿宽松连帽外套、短发、耳机并携带乐器包。故事无配音、少文字，主要通过表演和环境变化表达。

## 音乐策略

原型优先使用授权清晰、标明 BPM 且提供 stems 或 MIDI 的现成电子流行音乐。每首歌至少拆分为电子鼓、合成贝斯、和弦铺底和主旋律四轨。所有下载必须保存作者、来源、授权文本和日期。

普通立体声 MP3 不适合作为核心素材，因为玩法需要独立控制各个音轨。正式公开前必须再次审查授权；若替换音乐，需要重做对应谱面。

## 技术架构

项目使用 Godot 4.x：

- **Conductor**：以音频播放位置为唯一节拍时钟，并应用玩家校准偏移。
- **Chart Loader**：从 JSON 读取 BPM、乐器、时间点、输入类型和难度。
- **Rhythm Judge**：把输入时间与最近的未处理音符比较，返回判定与偏差。
- **Track Mixer**：同步管理四条 stems，确保循环和增减音轨时不漂移。
- **Stage Director**：根据当前音轨、连击、热度和判定驱动动画与灯光。
- **Progression**：保存关卡解锁、最高评分和设置。

音乐数据、谱面数据、关卡逻辑和视觉场景彼此分离，以便替换占位音乐而不重写核心代码。

## 异常处理

- 失去窗口焦点时自动暂停，并在恢复时重新同步音轨。
- 检测音频设备变化后暂停关卡，提示重新校准。
- 音轨加载失败时阻止开始关卡并显示具体文件名。
- 谱面格式错误时在开发构建中报告事件索引和字段。
- 帧率下降不改变判定时钟；视觉表现追赶音频时间。
- 存档损坏时保留损坏文件副本并创建默认存档。

## 测试与验收

- 纯逻辑单元测试覆盖 Perfect、Good、Miss、重复输入和校准偏移。
- 自动验证四条音轨时长、采样率和循环点一致。
- 使用调试 HUD 显示歌曲时间、最近输入偏差、当前乐器和音轨状态。
- 在键盘、Xbox 布局手柄、有线耳机和蓝牙耳机上分别测试。
- Demo 全流程保持 60 FPS；正常游玩不出现音轨累积漂移。
- 六关均可完成，失误不会造成软锁或强制重开。

## 明确不做

Demo 不包含 macOS/Linux、在线功能、排行榜、Steam 成就、创意工坊、捏脸、服装商店、配音、复杂剧情分支或关卡编辑器。
