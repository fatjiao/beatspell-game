# ADR-0001: 使用纯逻辑节奏核心与单场景表现层

## Status

Accepted

## Context

Demo 需要快速验证节奏技能与 Boss 决策，但手感参数会频繁调整。若判定、战斗和绘制全部写在一个场景脚本里，调试时容易互相影响，也很难自动验证。

## Decision

使用两个无节点、可测试的 `RefCounted` 模块：`SpellCommandBuffer` 和 `BattleModel`。前者在整拍网格上记录动作，并由结束键立即触发节奏识别；一个 Godot `Control` 场景负责实时输入、音频和绘制。音乐与视觉使用同一播放时钟，输入额外应用用户校准偏移。

## Consequences

### Positive

- 技能配方与战斗数值可独立测试。
- 场景可以完全重画而不改变节奏规则。
- 不引入数据库、网络或插件，适合一人 Demo。

### Negative

- 场景控制器仍会包含较多表现代码。
- 以后增加多首歌时需要再抽出谱面数据层。

### Neutral

- 旧“一人乐队”场景保留在仓库中，但不再是主场景。

## Alternatives Considered

- **全部写进一个脚本**：实现更快，但节奏与战斗难以回归测试。
- **完整 ECS**：扩展性强，但对单场 Boss Demo 过度设计。
- **外部音游框架**：引入成本和授权风险高，不适合当前预算。
